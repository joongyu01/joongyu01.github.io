LAST 10 MINUTES

이유와 함께 기억할 여덟 가지

1장 개념 복습용입니다. 전체 시험 범위 1~3장은 핵심정리에서 이어 보세요.

01 / 주소

IP는 목적지, MAC은 다음 전달 대상

원격 서버로 보낼 때 목적지 IP는 서버, 첫 프레임의 목적지 MAC은 게이트웨이. 포트는 호스트 안의 통신 종점을 구분한다.

라우터마다 MAC은 바뀌어도 종단 IP는 보통 유지. NAT는 예외.
02 / 계층

세그먼트 → 패킷 → 프레임

응용 데이터를 TCP 세그먼트에, 세그먼트를 IP 패킷에, 패킷을 링크 프레임에 넣는다. 수신은 역순이다.

스위치는 MAC, 라우터는 IP를 기준으로 전달.
03 / 단위

200 Mbps ÷ 8 = 25 MB/s

1 byte는 8 bit. b와 B를 구분한다. 회선 속도는 실제 파일 처리량의 보장이 아니다.

bit → byte는 ÷8. 반대는 ×8.
04 / 성능

대역폭이 넓어도 지연은 클 수 있다

전송 지연은 L/R, 전파 지연은 d/v. 큐잉·처리 지연도 있다. 실시간 통신은 지터와 손실도 중요하다.

많이 보낼 수 있는가 ≠ 빨리 도착하는가.
05 / ping

ICMP 성공이 웹 성공은 아니다

ping은 도달성과 RTT의 단서다. 웹은 DNS, TCP 또는 QUIC, TLS, HTTP도 통과해야 한다.

ping 실패도 ICMP 차단 때문일 수 있다.
06 / tracert

한 홉의 RTT는 내 PC 기준 왕복 시간

바로 앞 홉과의 구간 지연이 아니다. 별표는 탐색 응답을 못 받았다는 뜻이며 단선 확정은 아니다.

한 홉만 느림과 이후 홉도 계속 느림을 구분.
07 / DNS

이름 문제와 연결 문제를 나눠 보기

IP는 되는데 이름을 못 찾으면 nslookup. IP가 여러 개 나오는 것은 CDN·부하 분산일 수 있다.

DNS 정상이어도 포트·TLS·앱은 따로 확인.
08 / 서술형

결론 → 이유 → 확인 방법 → 한계

“게이트웨이는 되지만 외부 IP가 실패하므로 WAN·경로·정책을 조사한다. 다른 목적지와 앱도 비교하며 ICMP 차단 가능성은 남겨 둔다.”

무조건·항상으로 단정하기보다 근거로 범위를 좁히기.
