LAST 10 MINUTES

2장 마지막 핵심 여덟 가지

2장 강의 기반 복습용입니다. 전체 시험 범위 1~3장은 핵심정리에서 이어 보세요.

01 / HTTP

메서드와 메시지

GET 조회 / POST 제출·처리 / PUT 대체 / PATCH 일부 변경 / DELETE 삭제. HTTP/1.1은 시작 줄·헤더·빈 줄·본문으로 읽는다.

HTTP/2·3까지 같은 텍스트 형식이라고 일반화하지 않기.
02 / 상태 코드

401 인증, 403 거부, 404 없음

200 성공 / 204 본문 없는 성공 / 301·302 이동 / 304 변경 없음 / 500 서버 내부 오류.

304는 기존 캐시 본문 재사용.
03 / 쿠키

Set-Cookie 내려옴, Cookie 올라감

서버가 세션 식별자를 보내고 브라우저가 적용 대상 요청에 돌려준다. 서버 세션 상태와 쿠키 저장 위치를 구분한다.

쿠키에 비밀번호 원문이 반드시 들어가는 것은 아님.
04 / 캐시

ETag → If-None-Match → 304

기존 ETag로 조건부 GET을 보내고 같으면 304, 바뀌면 새 본문의 200. CDN은 가까운 서버에서 제공한다.

쿠키는 상태 정보, 캐시는 자원 재사용.
05 / HTTPS

기밀성·무결성·서버 인증

SNI는 접속하려는 서버 이름, SAN은 인증서에 유효한 이름. 이름·유효기간·신뢰 체인을 검증한다.

TLS 연결 보호가 판매자의 정직성을 보증하지는 않음.
06 / DNS

A v4 / AAAA v6 / MX 메일

CNAME 별칭 / NS 권한 서버. 재귀 리졸버가 캐시를 확인하고 필요하면 루트→TLD→권한 서버를 따라간다.

DNS TTL은 캐시 시간. UDP·TCP 53 모두 사용.
07 / 메일·포트

SMTP 보내기, IMAP 동기화

SMTP 25 서버 간 / 587 제출. POP3 110·보호된 연결 995, IMAP 143·보호된 연결 993. HTTP 80, HTTPS 443.

FTP 제어 21, 데이터 포트는 능동·수동 모드를 구분.
08 / 버전

HTTP/2 TCP / HTTP/3 QUIC

HTTP/2 다중화에도 TCP 손실 HOL은 남는다. QUIC은 UDP 위에서 신뢰성·스트림·보안을 구현한다.

UDP 기반이라고 QUIC도 신뢰성 없는 비연결인 것은 아님.
학습 근거와 확인 범위

2장 교안, 교수자 TCP 보충자료, 확보한 강의 영상 자막을 바탕으로 작성한 자체 복습 문제입니다. 강의 영상의 시간은 영상 시작 기준이며 각 해설에서 해당 근거를 확인할 수 있습니다. 자막 오인식은 교안과 계산으로 교정했습니다.

교재 연습문제 원문·번호·공식 답안과는 다릅니다. 문제의 수치 변형과 선택지는 새로 작성했습니다. TCP 종합 문제는 교수자 보충자료의 수치를 사용했습니다.

기술 표현 대조: TCP · 혼잡 제어 · QUIC · HTTP 캐시. 이는 출제 확정의 근거가 아닙니다.

학습 기록은 장별로 이 브라우저에 저장되며 기기 간 동기화는 없습니다.
